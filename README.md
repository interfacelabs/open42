# Open42

> [!WARNING]
> Open42 is still a work in progress and is currently in beta. Some
> functionality may be incomplete, unstable, or broken while the project is
> being built. If you run into an issue or need help, email
> [support@open42.ai](mailto:support@open42.ai).

Open42 is a self-hostable Company Brain on top of
[gbrain](https://github.com/garrytan/gbrain). It owns the product shell:
auth, tenancy, chat, connectors, skills, metadata, and deployment. gbrain is an
immutable runtime dependency.

Community self-host is the default edition. Cloud-only code lives in
`packages/cloud/` and is loaded only when `OPEN42_EDITION=cloud`.

## Editions

| Edition | Default | Includes |
| --- | --- | --- |
| `community` | Yes | Single workspace, BYOK, optional Composio, no Stripe or Fly runtime code |
| `cloud` | No | Hosted Open42 billing, Stripe webhooks, Fly tenant provisioning |

The root repo is source-available under the Open42 Community License: you can
self-host Open42, including in production for your own organization, but you
cannot offer Open42 or substantially similar Open42 functionality as a hosted or
managed cloud service to third parties without a commercial license.
`packages/cloud/` has its own commercial, source-available license.

## Self-Hosted Quickstart

Create a free Supabase project first, then run:

```bash
nvm use
npm install
npm run setup
docker compose -f docker-compose.community.yml up --build
```

`npm run setup` writes `.env`, generates `OPEN42_KEK`, `SESSION_SECRET`,
`OPEN42_INGEST_HMAC_SECRET`, `OPEN42_SINGLE_WORKSPACE_ID`, and
`OPEN42_TENANT_PROXY_TOKEN`, and prompts for the three Supabase values. The
first Supabase magic-link recipient becomes the workspace owner.

Open the app at http://localhost:3000/sign_in. After sign-in, add workspace
provider keys in Settings -> API Keys before using chat or ingest. Community
edition does not use shared Open42 provider keys unless you explicitly set
`OPEN42_ALLOW_SHARED_KEYS=true`.

### Supabase Auth URLs

Supabase Auth must point back to the Open42 web app. In Supabase Dashboard ->
Authentication -> URL Configuration:

- Set Site URL to your deployed `WEB_PUBLIC_URL`.
- Add `WEB_PUBLIC_URL/sign_in` to Redirect URLs.
- Add `WEB_PUBLIC_URL/auth/invite/accept**` to Redirect URLs for invite links
  that carry an `invite_id`.
- Keep `http://localhost:3000/**` only as an additional local-development
  redirect URL, not as the production Site URL.

If you customize the Supabase Magic Link email template, keep the link based on
`{{ .ConfirmationURL }}`. For a custom token-hash link, build it from
`{{ .RedirectTo }}` instead of `{{ .SiteURL }}` so production emails do not use
the local Site URL.

### Managed Env Or Secret Store

For container platforms or external secret stores:

```bash
npm run setup -- --print
```

Paste the printed `KEY=value` lines into your platform env UI, Compose override,
Vault, Doppler, 1Password CLI, or equivalent. No `.env` file is required.

To write somewhere other than `.env`:

```bash
npm run setup -- --env-file /path/to/open42.env
```

## Required Community Env

| Var | What |
| --- | --- |
| `OPEN42_EDITION=community` | Optional because community is the default |
| `DATABASE_URL` | Open42 metadata Postgres URL |
| `OPEN42_KEK` | 32-byte hex secret generated by `npm run setup` |
| `SESSION_SECRET` | Session signing secret generated by `npm run setup` |
| `OPEN42_INGEST_HMAC_SECRET` | OAuth/install state signing secret generated by `npm run setup` |
| `SUPABASE_URL` | Supabase project URL |
| `SUPABASE_ANON_KEY` | Supabase anon key |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase service role key |
| `GBRAIN_BASE_URL` | Community Compose gbrain URL, normally `http://gbrain:8080` |
| `OPEN42_SINGLE_WORKSPACE_ID` | Fixed workspace id generated by setup |
| `OPEN42_TENANT_PROXY_TOKEN` | Tenant proxy token generated by setup |

Optional flags:

| Var | Default | What |
| --- | --- | --- |
| `OPEN42_ALLOW_MULTI_WORKSPACE` | `false` in community | Allows creating more than one workspace |
| `OPEN42_ALLOW_SHARED_KEYS` | `false` in community | Allows fallback to server `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` |
| `COMPOSIO_API_KEY` | unset | Enables Composio-backed connectors |
| `OPEN42_DISABLE_COMPOSIO` | `false` | Hard-disables Composio even if a key is set |
| `RESEND_API_KEY` | unset | Sends invite emails and landing waitlist notifications |
| `RESEND_FROM_ADDRESS` | `Open42 <noreply@mail.open42.ai>` | From address for Resend-delivered email |
| `OPEN42_WAITLIST_NOTIFY_EMAIL` | `riccardo@interfacelabs.ai` | Landing waitlist notification recipient |

See `.env.community.example` for a full annotated environment file.

## GitHub Repo Sync For Self-Host

Open42 syncs GitHub repositories through a GitHub App and then delegates repo
syncing to gbrain. Markdown and MDX files are indexed. Private repositories use
Open42's narrow git bridge so credentials are never embedded in clone URLs.

Recommended self-host setup:

1. Give the web and API services public HTTPS URLs. Webhooks and private repo
   cloning need the API URL to be reachable by GitHub and by gbrain:

   ```env
   WEB_PUBLIC_URL=https://open42.example.com
   API_PUBLIC_URL=https://api.open42.example.com
   GITHUB_GIT_PROXY_PUBLIC_URL=https://api.open42.example.com
   ```

2. Run setup and migrations:

   ```bash
   npm run setup
   npm run db:migrate -w @open42/api
   ```

3. Start Open42, sign in as the workspace owner, then open
   Settings -> Connections -> Add -> GitHub.

4. Open42 will send you through GitHub's App Manifest flow, create a
   workspace-owned GitHub App with the right permissions and webhook URL, then
   continue to app installation and repository selection.

Manual deployment-wide GitHub App setup is also supported. Use this when one
self-host deployment should share a single GitHub App across all workspaces:

1. Create a GitHub App:
   - Personal account: https://github.com/settings/apps/new
   - Organization: `https://github.com/organizations/YOUR_ORG/settings/apps/new`

2. Configure the app:

   | GitHub App field | Value |
   | --- | --- |
   | Homepage URL | `WEB_PUBLIC_URL` |
   | Callback URL | `WEB_PUBLIC_URL/connections/github/callback` |
   | Setup URL | `WEB_PUBLIC_URL/connections/github/callback` |
   | Webhook URL | `API_PUBLIC_URL/webhooks/github` |
   | Webhook secret | A random secret, for example `openssl rand -hex 32` |

3. Set repository permissions:

   | Permission | Access |
   | --- | --- |
   | Contents | Read-only |
   | Metadata | Read-only |

4. Subscribe to webhook events:
   - Push
   - Installation

5. Choose where the app can be installed. Use "Only on this account" for a
   single-org self-host install. Use "Any account" only when your self-host
   deployment needs installs across multiple GitHub accounts.

6. Generate a private key from the GitHub App settings page. Put the app values
   in `.env`:

   ```env
   GITHUB_APP_ID=123456
   GITHUB_APP_SLUG=open42-your-company
   GITHUB_WEBHOOK_SECRET=your-random-webhook-secret
   GITHUB_GIT_PROXY_PUBLIC_URL=https://api.open42.example.com
   GITHUB_APP_PRIVATE_KEY=-----BEGIN RSA PRIVATE KEY-----\n...\n-----END RSA PRIVATE KEY-----\n
   ```

   To convert the downloaded `.pem` file into a single-line `.env` value:

   ```bash
   python3 -c 'print(open("your-private-key.pem").read().replace("\n", "\\n"))'
   ```

7. Restart the API, then connect GitHub from Settings -> Connections -> Add.

## Local Development

```bash
npm install
cp .env.example .env.local
npm run db:up
npm run db:push
npm run dev
```

For local development, `TENANT_PROVISIONER=local-docker` starts one gbrain
container per workspace. For Compose self-host, `TENANT_PROVISIONER=compose`
points Open42 at the shared `gbrain` service.

## Commands

| Command | What it does |
| --- | --- |
| `npm run setup` | Generate or upsert self-host secrets into `.env` |
| `npm run setup -- --print` | Print generated env without writing a file |
| `npm run dev` | Run web and API together |
| `npm run db:up` | Start local Postgres and Redis for development |
| `npm run db:push` | Apply the current Drizzle schema in development |
| `npm run db:migrate` | Run committed Drizzle migrations |
| `npm run tenant:build` | Build the gbrain tenant image |
| `npm run typecheck` | TypeScript across workspaces |
| `npm run lint` | ESLint across workspaces |
| `npm run test` | API unit/integration tests |
| `npm run test:e2e` | Playwright tests |

Cloud-only Fly tenant scripts live under `packages/cloud/scripts/`.

## Architecture Notes

- Open42 metadata is separate from tenant brain data.
- gbrain is accessed only through HTTP MCP and OAuth.
- Provider keys never enter the tenant runtime. gbrain calls Open42's provider
  proxy with a tenant proxy token; Open42 resolves BYOK or an allowed shared key.
- Every tenant-scoped product route authorizes through `memberships`, not
  `users.current_workspace_id`.
- Community migrations contain only core metadata tables. Cloud billing and
  Stripe webhook tables live in `packages/cloud/migrations/`.
